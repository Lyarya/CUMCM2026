# Stage 2B：Q2 期望成本随机 MILP 检查点

本检查点只实现问题二的第一版期望成本随机 MILP，不含 CVaR、风险参数扫描、问题三或问题四。
优化器只通过 `src/problem2/forecast_interface.py::get_q2_day_inputs` 读取冻结的点预测、50 个
成对负荷/光伏场景、固定电价和调用方传入的初始储能电量。负荷场景与光伏场景始终使用共同的
场景索引，没有分别重排或重新抽样。

对每个运营日，计划购电、充电、放电、充放电模式和储能电量是 0:00 确定的场景共享变量；
紧急购电与弃光是场景变量。各场景满足功率平衡，弃光非负且不超过该场景可用光伏，紧急购电
非负并按当时普通电价的 5 倍计费。目标函数为计划购电成本与 50 个等概率场景紧急购电成本的
均值之和。

问题二没有沿用问题一的硬约束 `E_start = E_end = 6000`。为防止逐日有限视界在最后时段无成本
放空电池，模型加入线性软终端项

```text
rho * |E_end - E_carried|
```

其中参考值 `E_carried` 是当天由调用方带入的初始电量，默认权重
`rho = eta_d * max(price) = 1.25568 元/kWh`，表示一单位内部储能在下一峰价时段的机会价值上界。
这是目标函数惩罚而非终端等式。第二天的初始电量始终取前一天求得的日末电量；测试也使用
非 6000 kWh 初值验证该链路不存在常数重置。正式数据下 334 天的最优日末电量恰好均为
6000 kWh，这是软终端项下的最优结果，不是代码中的每日重置条件。

完整期为 2025-02-01 至 2025-12-31，共 334 天。所有日期均由 PuLP 调用 HiGHS 得到
`Optimal` 状态；程序遇到任一非最优状态会立即停止。机器可读结果位于
`results/problem2/tables/`，包括逐日汇总、48096 行逐时段计划以及包含完整场景紧急购电和弃光
数组的压缩 NPZ。官方模板结果写入 `results/problem2/result2.xlsx`。

模型中的场景紧急购电用于 0:00 计划优化；正式执行结果则在计划固定后使用附件 2 的实际负荷
和实际光伏计算。`result2.xlsx` 的“紧急购电量”工作表填写实际紧急购电，不再填写场景均值。
论文表 3 仅选取题面指定的 2025.3.20、2025.6.21、2025.9.23 和 2025.12.21，并严格采用
每个日期下“时间段、购电量”两列的横向分组形式。对应机器可读文件为
`table_p2_table3_emergency.csv`，LaTeX 表为 `table_p2_table3_emergency.tex`。
